# سامانه هوشمند جمع‌آوری و آرشیو کانال‌های تلگرام

برنامه‌ای کامل، فارسی و راست‌به‌چپ برای **افزودن کانال‌های تلگرام، دریافت خودکار زمان‌بندی‌شده مطالب، جلوگیری کامل از تکرار پست‌ها و خروجی گرفتن در قالب Excel و SQLite**.

- **تک‌فایل و بدون نیاز به سرور جداگانه:** پایگاه داده SQLite داخلی، بدون نیاز به MySQL/PostgreSQL
- **دریافت ترکیبی (Hybrid):** اسکرپ نسخه وب عمومی `t.me/s/<channel>` (بدون اکانت) + موتور رسمی `Telethon` (برای کانال‌های خصوصی)
- **ضدتکرار واقعی:** ذخیره `last_message_id` هر کانال + محدودیت `UNIQUE(channel_id, message_id)` در سطح پایگاه داده
- **اولین دریافت = فقط ۱۰ پست آخر**، دریافت‌های بعدی = فقط پست‌های جدیدتر از آخرین شناسه ذخیره‌شده
- **تفکیک ساختارمند:** لینک مستقیم پست، تاریخ شمسی، تاریخ میلادی، ساعت انتشار، متن، نوع رسانه و بازدید در ستون‌های جداگانه
- **رابط وب فارسی RTL** بدون هیچ CDN یا فونت اینترنتی (کاملاً آفلاین)

## پیش‌نیازها و نصب سریع

- **Python 3.10 یا بالاتر** (پیشنهاد: 3.11)
- دسترسی اینترنت به `t.me` (در صورت محدودیت، پروکسی تنظیم کنید)

### ویندوز

روی فایل `start_windows.bat` **دوبار کلیک** کنید. اسکریپت به‌صورت خودکار محیط مجازی می‌سازد، وابستگی‌ها را نصب و مرورگر را باز می‌کند.

### لینوکس / مک

```bash
chmod +x start_linux_mac.sh
./start_linux_mac.sh
```

### نصب دستی (همه سیستم‌عامل‌ها)

```bash
python3 -m venv .venv
source .venv/bin/activate          # در ویندوز: .venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

> **نیازی به Microsoft C++ Build Tools نیست.** فایل `requirements.txt` عمداً از
> `uvicorn[standard]` استفاده نمی‌کند و همه بسته‌ها به‌صورت wheel آماده نصب می‌شوند.
>
> اگر کانال **خصوصی** دارید، موتور اختیاری Telethon را جداگانه نصب کنید:
> ```bash
> pip install -r requirements-telethon.txt
> ```
> بدون این بسته هم برنامه کامل اجرا می‌شود و فقط کانال‌های عمومی با موتور وب دریافت می‌شوند.

سپس در مرورگر به آدرس زیر بروید:

```
http://localhost:8000
```

## اجرا

```bash
python run.py                      # اجرا روی 0.0.0.0:8000 (در صورت اشغال، پورت آزاد بعدی)
python run.py --port 9000          # تغییر پورت
python run.py --strict-port        # اگر پورت اشغال بود، متوقف شو (پورت را عوض نکن)
python run.py --reload             # حالت توسعه
python run.py --host 127.0.0.1     # فقط دسترسی محلی
```

همچنین می‌توان مستقیماً از uvicorn استفاده کرد:

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## راهنمای استفاده از پنل

پنل دارای شش زبانه است:

### ۱) مدیریت کانال‌ها و زمان‌بندی

1. آدرس کانال را وارد کنید؛ همه این قالب‌ها پذیرفته می‌شوند:
   - `@channel_name`
   - `channel_name`
   - `https://t.me/channel_name`
   - `https://t.me/s/channel_name`
   - `https://t.me/channel_name/1234` (شناسه پست نادیده گرفته می‌شود)
   - لینک خصوصی `https://t.me/+AbCdEf...` یا `https://t.me/c/1234567890/42` (نیازمند Telethon)
2. بازه زمانی بررسی خودکار را مشخص کنید (مثلاً «هر ۶ ساعت» یا «هر ۳ روز»). دکمه‌های میان‌بر بالای فیلد، انتخاب را سریع می‌کنند.
3. تعداد پست‌های **اولین دریافت** (پیش‌فرض ۱۰) را تعیین کنید.
4. اگر «دریافت فوری» تیک داشته باشد، بلافاصله همان ۱۰ پست آخر ذخیره می‌شود.

در جدول کانال‌ها، ستون **«آخرین شناسه پیام (ضدتکرار)»** نشان می‌دهد دریافت بعدی از کدام پیام به بعد ادامه می‌یابد. اگر «—» باشد یعنی هنوز اولین دریافت انجام نشده است.

### ۲) آرشیو مطالب ذخیره‌شده

- فیلتر بر اساس **کانال**، **کلیدواژه**، **بازه تاریخ** و **نوع محتوا**
- فیلدهای تاریخ، هم تاریخ شمسی (`1405/08/17`) و هم میلادی (`2026-11-08`) را قبول می‌کنند
- جدول شامل: کانال، شناسه پیام، تاریخ شمسی، تاریخ میلادی، ساعت، نوع محتوا، بازدید، متن و لینک مستقیم پست
- دکمه «جزئیات» متن کامل پست را با امکان کپی متن یا کپی لینک نمایش می‌دهد
- صفحه‌بندی ۲۵ ردیفی برای آرشیوهای بزرگ

### ۳) حذف مطالب (دو روش)

در پنل **دو روش** برای حذف وجود دارد:

#### روش الف — تیک زدن ردیف‌ها در جدول آرشیو

در زبانه «آرشیو مطالب» کنار هر ردیف یک **چک‌باکس** هست:

- تیک زدن چند ردیف → نوار آبی بالای جدول ظاهر می‌شود با شمارنده و دکمه **«حذف موارد انتخاب‌شده»**
- چک‌باکس هدر جدول = **انتخاب/لغو همه ردیف‌های همین صفحه**
- دکمه **«انتخاب همه نتایج فیلتر (نه فقط این صفحه)»** = انتخاب تمام مطالبی که با فیلتر فعلی
  مطابقت دارند، حتی اگر در صفحه‌های بعدی باشند (مثلاً ۲۵۰ مطلب در ۱۰ صفحه)

#### روش ب — حذف با فیلتر در زبانه «حذف و پاک‌سازی»

زبانه پنجم پنل، ترکیب آزاد این فیلترها را می‌پذیرد (هر فیلتر خالی = همه):

| فیلتر | نمونه |
| --- | --- |
| کانال | یک کانال خاص |
| بازه زمانی | `1405/08/01` تا `1405/08/30` یا `2026-11-01` تا `2026-11-30` |
| نوع محتوا | متن / تصویر / ویدیو / فایل / صوت / نظرسنجی |
| جستجو | مثلاً «تبلیغ» — فقط مطالبی که این عبارت در متن یا آدرسشان باشد |

دکمه **«پیش‌نمایش تعداد»** پیش از حذف دقیقاً می‌گوید چند مطلب مطابق شرایط است.

> **گزینه مهم «ریست شناسه آخرین پیام»** (پیش‌فرض روشن): پس از حذف، `last_message_id` کانال‌های
> متأثر پاک می‌شود تا دریافت بعدی از ابتدا انجام شود و همان ۱۰ مطلب آخر دوباره ذخیره شوند.
> بدون این گزینه، مطالبی که حذف کرده‌اید **هرگز دوباره دریافت نمی‌شوند**.

#### پاک‌سازی کلی (Danger Zone)

| دکمه | چه چیزی پاک می‌شود | کانال‌ها |
| --- | --- | --- |
| پاک کردن همه مطالب | همه مطالب + گزارش‌های دریافت | حفظ می‌شوند (شناسه‌ها ریست) |
| حذف کامل همه داده‌ها | مطالب + گزارش‌ها + کانال‌ها | حذف می‌شوند (تأیید با تایپ «حذف») |
| پاک کردن گزارش‌ها | فقط تاریخچه دریافت | دست‌نخورده |
| حذف کانال | یک کانال + مطالب و گزارش‌هایش | همان یکی |

تنظیمات (پروکسی، Telethon، منطقه زمانی) در هیچ‌کدام از این عملیات‌ها پاک نمی‌شود.

> پیش از پاک‌سازی کلی، از زبانه آرشیو یک **خروجی SQLite** بگیرید؛ حذف قابل بازگشت نیست.

### ۴) گزارش دریافت و تاریخچه

هر بار دریافت (خودکار یا دستی) یک ردیف ثبت می‌کند:

| ستون | معنی |
| --- | --- |
| زمان اجرا | تاریخ شمسی و ساعت محلی اجرا |
| نحوه اجرا | `دستی` یا `زمان‌بندی خودکار` |
| موتور | `وب عمومی` یا `Telethon` |
| پست‌های جدید | تعداد رکوردهای واقعاً درج‌شده (بدون تکرار) |
| تغییر شناسه | `قبل ← بعد` برای مقایسه `last_message_id` |
| نتیجه | موفق یا خطا همراه با متن خطا (مثلاً قطعی شبکه یا بسته بودن پیش‌نمایش وب) |

### ۵) پشتیبان‌گیری و بازیابی

یک فایل **JSON سبک** که فقط شامل «فهرست کانال‌ها + تنظیمات» است — نه مطالب آرشیو.
برای جابه‌جایی برنامه به سیستم دیگر یا بازگردانی تنظیمات پس از نصب تازه.

#### گرفتن پشتیبان

در زبانه «پشتیبان‌گیری و بازیابی»:

| گزینه | پیش‌فرض | توضیح |
| --- | --- | --- |
| تنظیمات هم در فایل باشد | ✅ روشن | حالت دریافت، منطقه زمانی، پروکسی، Telethon |
| کلیدهای حساس هم ذخیره شوند | ❌ خاموش | `api_hash` و رمز پروکسی — برای امنیت نوشته نمی‌شوند |
| فقط کانال‌های فعال | ❌ خاموش | برای پشتیبان سبک‌تر |

دکمه **«پیش‌نمایش محتوا»** فهرست کانال‌ها و تعداد تنظیمات را قبل از دانلود نشان می‌دهد.
نام فایل: `telegram_backup_20261109_121522.json`

#### بازیابی

1. فایل `.json` را انتخاب کنید
2. **«بررسی فایل»** → نمایش می‌دهد چند کانال جدید است و چند تا از قبل وجود دارد
3. یکی از دو روش را انتخاب کنید:

| روش | رفتار |
| --- | --- |
| **ادغام** (پیش‌فرض) | کانال‌های فایل اضافه یا به‌روزرسانی می‌شوند؛ **هیچ کانال فعلی حذف نمی‌شود** |
| **جایگزینی کامل** | ابتدا فهرست کانال‌ها و مطالبشان پاک می‌شود، سپس فایل بارگذاری می‌گردد |

4. گزینه تنظیمات:
   - **بدون «جایگزینی تنظیمات»** → فقط کلیدهای خالی پر می‌شوند (مقادیر فعلی شما امن است)
   - **با «جایگزینی تنظیمات»** → مقادیر فایل روی تنظیمات فعلی نوشته می‌شود

> **نکته مهم:** اگر آرشیو مطالب کانالی خالی باشد، `last_message_id` از فایل بازگردانی
> **نمی‌شود** (و یک هشدار فارسی نمایش داده می‌شود). دلیلش این است که بدون مطالب، نگه داشتن
> شناسه بالا باعث می‌شود مطالب آینده از دست بروند؛ بنابراین دریافت از ابتدا انجام می‌شود.

> فایل پشتیبان، مطالب را شامل نمی‌شود. برای پشتیبان کامل (کانال‌ها + مطالب + تنظیمات)
> از **خروجی SQLite** در زبانه آرشیو استفاده کنید — آن فایل یک دیتابیس کامل است.

### ۶) تنظیمات، پروکسی و اکانت تلگرام

- **روش دریافت:** هوشمند (پیشنهادی) / فقط وب / فقط Telethon
- **منطقه زمانی** برای تفکیک تاریخ و ساعت (`Asia/Tehran` پیش‌فرض)
- **تعداد پیش‌فرض اولین دریافت**
- **پروکسی:** SOCKS5 یا HTTP با آدرس، پورت و نام کاربری/رمز اختیاری
- **اتصال Telethon:** ورود با شماره موبایل + کد تایید + رمز دو مرحله‌ای

## ساختار داده‌ها و جدول‌ها

پایگاه داده در `data/telegram_collector.sqlite` با حالت **WAL** (نوشتن و خواندن هم‌زمان) ساخته می‌شود.

### جدول `channels`

| ستون | نوع | توضیح |
| --- | --- | --- |
| `id` | INTEGER PK | شناسه داخلی |
| `channel_key` | TEXT UNIQUE | کلید یکتای کانال (یوزرنیم lowercase یا `id:` / `invite:`) |
| `channel_input` | TEXT | ورودی خام کاربر |
| `username` | TEXT | یوزرنیم عمومی (برای کانال خصوصی `NULL`) |
| `canonical_url` | TEXT | آدرس متعارف `https://t.me/...` |
| `web_preview_url` | TEXT | آدرس پیش‌نمایش وب `https://t.me/s/...` |
| `title` | TEXT | عنوان کانال |
| `is_private` | INTEGER | ۰/۱ |
| `interval_value` + `interval_unit` | REAL + TEXT | بازه زمانی به‌صورت خام (`6` + `hours`) |
| `interval_minutes` | INTEGER | بازه نرمال‌شده به دقیقه (برای محاسبات زمان‌بند) |
| `initial_limit` | INTEGER | تعداد پست اولین دریافت (پیش‌فرض ۱۰) |
| **`last_message_id`** | INTEGER | **شناسه آخرین پیام ذخیره‌شده — قلب منطق ضدتکرار** |
| `last_post_url` / `last_post_at` | TEXT | آدرس و زمان آخرین پست |
| `is_active` | INTEGER | فعال بودن زمان‌بندی خودکار |
| `last_fetched_at` / `next_fetch_at` | TEXT | زمان آخرین دریافت / دریافت بعدی (UTC ISO) |
| `last_status` / `last_error` | TEXT | `ok` / `error` / `pending` / `syncing` و متن خطا |

### جدول `posts`

| ستون | نوع | توضیح |
| --- | --- | --- |
| `id` | INTEGER PK | شناسه رکورد |
| `channel_id` | INTEGER FK | ارجاع به کانال (`ON DELETE CASCADE`) |
| `channel_username` / `channel_title` | TEXT | اطلاعات کانال در زمان درج |
| `message_id` | INTEGER | شناسه پیام تلگرام |
| **`post_url`** | TEXT | **لینک مستقیم پست** `https://t.me/<chan>/<id>` |
| **`published_jalali_date`** | TEXT | **تاریخ شمسی** `YYYY/MM/DD` |
| **`published_date`** | TEXT | **تاریخ میلادی** `YYYY-MM-DD` |
| **`published_time`** | TEXT | **ساعت انتشار** `HH:MM:SS` |
| `published_at_utc` | TEXT | زمان دقیق UTC (`...Z`) برای مرتب‌سازی |
| `content` | TEXT | متن پست |
| `media_type` | TEXT | `text` / `photo` / `video` / `document` / `voice` / `poll` |
| `media_url` | TEXT | آدرس رسانه در صورت وجود |
| `views` | INTEGER | تعداد بازدید |
| `fetched_at` | TEXT | زمان درج رکورد |
| **UNIQUE** | — | **`UNIQUE(channel_id, message_id)`** |

### جدول `fetch_logs`

تاریخچه هر دریافت: `channel_id`, `channel_title`, `trigger_type`, `source_mode`, `fetched_count`, `new_saved_count`, `previous_last_message_id`, `new_last_message_id`, `status`, `message`, `duration_ms`, `created_at`.

## منطق ضدتکرار (Deduplication)

منطق در سه لایه پیاده شده است:

```
لایه ۱ — تصمیم بر اساس last_message_id (در SyncManager)
    اگر last_message_id IS NULL  →  فقط ۱۰ پست آخر (initial_limit)
    وگرنه                        →  پست‌هایی که message_id > last_message_id

لایه ۲ — محدودیت پایگاه داده
    UNIQUE(channel_id, message_id) + INSERT OR IGNORE
    → حتی اگر منطق لایه ۱ دور زده شود، رکورد تکراری هرگز درج نمی‌شود

لایه ۳ — به‌روزرسانی اتمیک
    درج پست‌ها، ارتقای last_message_id و ثبت گزارش در یک تراکنش
    → قطع برق یا خطای نیمه‌کاره باعث ناسازگاری نمی‌شود
```

**مثال عملی:**

| مرحله | پست‌های موجود در کانال | `last_message_id` قبل | ذخیره‌شده | `last_message_id` بعد |
| --- | --- | --- | --- | --- |
| اولین دریافت | ۱ تا ۵۰ | `NULL` | ۴۱ تا ۵۰ (۱۰ پست) | ۵۰ |
| دریافت دوم (۳ پست جدید) | ۱ تا ۵۳ | ۵۰ | ۵۱، ۵۲، ۵۳ | ۵۳ |
| دریافت سوم (بدون پست جدید) | ۱ تا ۵۳ | ۵۳ | — | ۵۳ |

> اگر می‌خواهید یک کانال از صفر دوباره دریافت شود، از دکمه **ریست** (یا `POST /api/channels/{id}/reset`) استفاده کنید؛ با `delete_posts=true` آرشیو آن کانال هم پاک می‌شود.

## موتورهای دریافت: وب و Telethon

### ۱. اسکرپر وب عمومی (پیش‌فرض — بدون اکانت)

- آدرس: `https://t.me/s/<username>`
- **مزیت:** بدون نیاز به شماره موبایل، `api_id` یا `api_hash`
- **محدودیت:** فقط کانال‌های عمومی که پیش‌نمایش وب آن‌ها فعال است
- صفحه‌بندی معکوس با `?before=<message_id>` برای پر کردن فاصله زمانی
- حذف بلوک نقل‌قول (reply) تا متن پاسخ با متن اصل پست مخلوط نشود
- تبدیل `<br>` به خط جدید، تشخیص نوع رسانه و تبدیل بازدید (`1.2K` → `1200`)

### ۲. موتور رسمی Telethon (برای کانال خصوصی یا پیش‌نمایش بسته)

1. به [my.telegram.org](https://my.telegram.org) بروید → `API development tools`
2. یک اپلیکیشن بسازید و `api_id` و `api_hash` را بردارید
3. در پنل، زبانه «تنظیمات» → بخش Telethon → کلیدها را وارد و ذخیره کنید
4. شماره موبایل با پیش‌شماره کشور (`+98912...`) را وارد و «ارسال کد تایید» را بزنید
5. کد دریافتی در تلگرام را وارد کنید (اگر رمز دو مرحله‌ای دارید، آن را هم وارد کنید)

> **پیش‌نیاز نرم‌افزاری:** اگر هنگام نصب فقط `requirements.txt` را نصب کرده‌اید، ابتدا
> `pip install -r requirements-telethon.txt` را اجرا کنید. نبودن Telethon مانع اجرای
> برنامه نمی‌شود؛ فقط ورود با اکانت و کانال‌های خصوصی غیرفعال می‌مانند و پنل هشدار می‌دهد.

نشست در `data/telethon_session.session` ذخیره می‌شود و در اجراهای بعدی نیازی به ورود مجدد نیست. برای حذف نشست، دکمه «خروج و حذف نشست» را بزنید.

## خروجی Excel و SQLite

### Excel (`.xlsx`)

- **شیت ۱ «مطالب کانال‌ها»:** ردیف، عنوان کانال، شناسه کانال، شناسه پیام، **آدرس مستقیم مطلب (لینک کلیک‌پذیر)**، **تاریخ شمسی**، **تاریخ میلادی**، **ساعت انتشار**، نوع محتوا، بازدید، متن مطلب، زمان دریافت
- **شیت ۲ «لیست کانال‌ها»:** کانال، آدرس، وضعیت، بازه زمانی، `last_message_id`، تعداد پست، آخرین و بعدی زمان دریافت
- جهت شیت‌ها **RTL**، سطر عنوان فریز شده، رنگ‌بندی راه‌راه، تنظیم عرض ستون‌ها
- پاک‌سازی کاراکترهای غیرمجاز XML و جلوگیری از تزریق فرمول (`=`, `+`, `-`, `@`)

### SQLite (`.sqlite`)

- کپی اتمیک با `sqlite3.backup()` — حتی در حین نوشتن زمان‌بند امن است
- `PRAGMA journal_mode = DELETE` تا فایل تک‌تکه و بدون `-wal` باشد
- **حذف خودکار اطلاعات حساس** (`telethon_api_hash`, `telethon_phone`, `proxy_password`, ...) از خروجی
- امکان خروجی **فیلترشده** (فقط پست‌های مطابق فیلتر فعلی) یا خروجی کامل
- `VACUUM` برای حجم بهینه

فایل‌های موقت خروجی SQLite پس از ارسال به کاربر با `BackgroundTask` حذف می‌شوند.

## پرسش‌های متداول و رفع اشکال

### خطای `[Errno 10048] ... bind on address ('0.0.0.0', 8000)` / WinError 10048

معنی خطا: **پورت ۸۰۰۰ همین حالا توسط برنامه دیگری (معمولاً همان برنامه که از قبل باز است) اشغال شده است.**
این خطا ربطی به نصب یا کد ندارد.

**به‌روزرسانی:** از نسخه جدید به بعد، برنامه دیگر با این خطا کرش نمی‌کند:

- اگر خودِ برنامه از قبل در حال اجرا باشد، پیام فارسی می‌دهد و آدرس پنل را نشان می‌دهد
  و بلافاصله خارج می‌شود (بدون crash).
- اگر برنامه دیگری پورت را گرفته باشد، **خودکار روی اولین پورت آزاد بعدی** (۸۰۰۱، ۸۰۰۲، ...) بالا می‌آید
  و آدرس درست را چاپ می‌کند.

**راه‌حل‌های دستی:**

```powershell
# ۱) بستن نسخه‌های قبلی با یک دوبار کلیک
stop_windows.bat

# ۲) انتخاب یک پورت خالی دیگر
start_windows.bat --port 8010
# یا
python run.py --port 8010

# ۳) اگر می‌خواهید در صورت اشغال بودن پورت، برنامه متوقف شود (نه تغییر پورت)
python run.py --port 8000 --strict-port
```

**مشاهده اینکه چه برنامه‌ای پورت را گرفته است:**

```powershell
netstat -ano | findstr :8000
tasklist /fi "pid eq <PID از خروجی بالا>"
```

در لینوکس/مک:

```bash
lsof -i :8000        # یا: ss -ltnp | grep 8000
kill -9 <PID>
```

> نکته: پنجره سیاه کنسول را با دکمه ✕ نبندید؛ چون ممکن است فرزند پروسه زنده بماند.
> همیشه `Ctrl + C` بزنید یا از `stop_windows.bat` استفاده کنید.

### خطای `Microsoft Visual C++ 14.0 or greater is required` هنگام نصب

این خطا مربوط به برنامه نیست؛ `pip` می‌خواهد بسته‌ای را از سورس کد کامپایل کند.
راه‌حل‌ها به ترتیب اولویت:

**۱) نسخه جدید پروژه را بگیرید (حل دائمی).**
فایل `requirements.txt` اصلاح شده و دیگر هیچ بسته کامپایل‌شونده‌ای (مثل `pyyaml` که
از `uvicorn[standard]` می‌آمد) نصب نمی‌کند:

```bash
git pull
rm -rf .venv                      # ویندوز: rmdir /s /q .venv
python -m venv .venv
.venv\Scripts\activate           # لینوکس/مک: source .venv/bin/activate
pip install --prefer-binary -r requirements.txt
python run.py
```

**۲) اجبار به استفاده از wheel آماده** (اگر باز هم pip سورس را انتخاب کرد):

```bash
pip install --only-binary=:all: --prefer-binary -r requirements.txt
```

**۳) اگر بسته‌ای واقعاً wheel نداشت**، پیش از نصب آن:
```bash
pip install --upgrade pip setuptools wheel
```

**۴) آخرین راه‌حل (اگر خواستید `uvicorn[standard]` را داشته باشید):**
نصب [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)
با انتخاب workload «Desktop development with C++». **برای این برنامه لازم نیست.**

**۵) نصب آفلاین روی سیستم بدون اینترنت:**
روی سیستمی که اینترنت دارد:
```bash
pip download --only-binary=:all: -d wheels -r requirements.txt
```
سپس پوشه `wheels` را به سیستم مقصد ببرید و اجرا کنید:
```bash
pip install --no-index --find-links wheels -r requirements.txt
```

> **نکته:** موتور Telethon اختیاری است. اگر نصب نشد، برنامه باز هم بالا می‌آید و
> کانال‌های عمومی را با موتور وب دریافت می‌کند؛ در پنل یک هشدار زرد نمایش داده می‌شود.

**پیش‌نمایش وب کانال در دسترس نیست.**
کانال خصوصی است یا مالک آن نمایش وب را بسته است. موتور Telethon را فعال کنید (بخش [Telethon](#۲-موتور-رسمی-telethon-برای-کانال-خصوصی-یا-پیشنمایش-بسته)).

**خطای اتصال / Timeout.**
دسترسی به `t.me` محدود است. در تنظیمات پروکسی SOCKS5 یا HTTP را فعال کنید.

**پست تکراری ذخیره شده؟**
نباید بشود؛ قید `UNIQUE(channel_id, message_id)` جلوی آن را می‌گیرد. بررسی کنید:

```bash
sqlite3 data/telegram_collector.sqlite \
  "SELECT channel_id, message_id, COUNT(*) c FROM posts GROUP BY 1,2 HAVING c > 1;"
```

خروجی خالی یعنی هیچ تکراری وجود ندارد. اگر شمارنده `new_saved_count` در گزارش صفر است، طبیعی است: یعنی پست جدیدی منتشر نشده بود.

**تاریخ شمسی یک ساعت جابه‌جاست.**
منطقه زمانی را در تنظیمات بررسی کنید (پیش‌فرض `Asia/Tehran`). تغییر منطقه زمانی روی پست‌های **جدید** اثر می‌گذارد؛ برای بازسازی، کانال را ریست کنید.

**زمان‌بند کار نمی‌کند.**
بج بالای صفحه باید «زمان‌بند خودکار فعال» باشد و کانال باید **فعال** باشد (`next_fetch_at` در آینده). `GET /api/overview` را بررسی کنید. تیک `coalesce` باعث می‌شود اجراهای عقب‌افتاده یک‌باره جبران شوند.

**سرور روی شبکه محلی در دسترس نیست.**
سرور به‌صورت پیش‌فرض روی `0.0.0.0` گوش می‌دهد؛ در ویندوز اجازه دسترسی `python.exe` را در فایروال بدهید.

**پشتیبان‌گیری.**
کافی است فایل `data/telegram_collector.sqlite` (به‌همراه `-wal` و `-shm` در صورت وجود) را کپی کنید، یا از پنل خروجی `.sqlite` بگیرید.

## ساختار پروژه

```
Telegram/
├── app/
│   ├── main.py                  # ساخت اپلیکیشن FastAPI و lifespan زمان‌بند

│   ├── database.py              # DatabaseManager: اسکیما، CRUD، تراکنش‌های اتمیک
│   ├── schemas.py               # مدل‌های Pydantic درخواست‌ها
│   ├── api/
│   │   └── routes.py            # تمام endpointهای /api
│   ├── collectors/
│   │   ├── base.py              # ساختارهای مشترک، خطا و تنظیم پروکسی
│   │   ├── web_scraper.py       # اسکرپر t.me/s/<channel>
│   │   ├── telethon_client.py   # موتور MTProto + ورود/خروج اکانت
│   │   └── manager.py           # SyncManager: انتخاب موتور، ضدتکرار، تراکنش
│   ├── services/
│   │   ├── scheduler.py         # APScheduler و بررسی کانال‌های سررسیده
│   │   └── exporter.py          # خروجی Excel و SQLite
│   ├── utils/
│   │   ├── channel_parser.py    # پارس و نرمال‌سازی آدرس کانال
│   │   └── jalali.py            # تبدیل و تفکیک تاریخ شمسی/میلادی/ساعت
│   ├── static/
│   │   ├── css/style.css        # استایل فارسی RTL
│   │   └── js/app.js            # منطق رابط کاربری
│   └── templates/index.html     # صفحه تک‌صفحه‌ای پنل
├── tests/                       # ۱۴۴ تست آفلاین pytest
├── data/                        # دیتابیس، نشست و خروجی‌ها (خودکار ساخته می‌شود)
├── run.py                       # نقطه شروع اجرای سرور
├── start_windows.bat            # اجرای آسان در ویندوز
├── stop_windows.bat             # بستن نسخه‌های در حال اجرا (رفع خطای پورت)
├── launcher.py                  # منطق راه‌انداز ویندوز (venv، نصب، پورت، مرورگر)
├── start_linux_mac.sh           # اجرای آسان در لینوکس/مک
├── Dockerfile
├── docker-compose.yml
├── requirements.txt             # وابستگی‌های اصلی (بدون نیاز به کامپایلر C)

└── pytest.ini
```

## مجوز و نکته حقوقی

این پروژه برای آرشیو شخصی و تحلیل محتوای کانال‌های عمومی طراحی شده است. رعایت قوانین تلگرام، شرایط استفاده و حقوق مالکیت محتوای کانال‌ها بر عهده کاربر است. استفاده از اکانت شخصی خود در Telethon و رعایت محدودیت‌های نرخ (Flood Wait) توصیه می‌شود.
